# Local integration contract

## Version 2 additions (authoritative over v1 fields below)

Model 2.0.0 adds settings `release_policy: sample|final` (default sample), `inspection_offset` (0..inspect_every-1). First piece always measured, later piece number modulo interval equals offset. Summary adds `released` (measured good only), `pending_release`, `supplemental_produced`, `final_inspections`, `release_on_time`, `cost_per_released_eur`. Parts add `inspection_kind: null|sample|final`, `observed_time_minutes`, `age_on_edge`. `playback_events` always contains production events, while optional `events` remains observation logging. `process.profile` contains server-computed ideal points `{x_mm,y_um}`, feed_mm_rev, height_um, width_mm. Final week policy checks unknown parts after nominal quota, replenishes measured deficits, and repeats until released target or schedule exhaustion. Trial final policy only inspects the requested gross count. Legacy files must not be claimed exactly reproducible under v2.

Python package `simulator`. Core owns `schemas.py`, `process.py`, `engine.py`, `scenarios/*.json`, and `tests/test_core.py`. Root owns API, setup, export and API tests. Frontend owns `frontend/` exclusively. No frontend simulation calculations.

API: GET `/api/scenarios` -> array of scenario objects (id, title, description, material, initial_diameter_mm, final_diameter_mm, length_mm, ra_limit_um, diameter_tolerance_mm, days, shift_minutes, defaults). POST `/api/simulate` takes Settings. GET `/api/health`. POST `/api/export/csv` takes Settings and returns per-part CSV. POST `/api/export/summary` takes Settings and returns Markdown summary. POST `/api/reproduce` takes {settings, model_version, scenario_snapshot} and returns recomputed result; validates snapshot against installed scenario.

Settings (all required defaults in schema): scenario_id='steel-shaft', mode='trial'|'week', speed_m_min=180, feed_mm_rev=0.18, change_after_parts=20, inspect_every=5, quantity=10 (trial count or good order target for week), seed=42, logging=true, stop_on_reject=false. Strict bounded validated inputs. Scenario second id='tight-finish', same geometry tighter quality. Defaults settings dictionary. Model_version='1.0.0'.

Core exports `simulate(settings: Settings) -> dict`, `load_scenarios() -> list[dict]`, `get_scenario(id) -> dict`. Results: {model_version, settings, scenario_snapshot, process, summary, parts, events}. process: {cutting_minutes, cycle_minutes, rpm_by_pass, theoretical_ra_um, tool_life_minutes, passes, removed_volume_cm3}. summary: {produced, good, rejected, inspected, detected_rejects, uninspected, tools_used, tool_changes, cutting_minutes, elapsed_minutes (calendar from Monday shift start), working_minutes (consumed scheduled), available_minutes, downtime_minutes: {handling, inspection, tool_change, shift_wait}, total_cost_eur, cost_per_good_eur:null|number, on_time, order_target, completion_fraction, final_wear, unused_minutes}. parts rows: {number, time_minutes, ra_um, diameter_mm, wear, good, inspected, observed_good:null|bool, tool_number}. events: {kind, start_minutes, duration_minutes, part_number:null|int}. Event kinds handling/cutting/inspection/tool_change/shift_wait. Day length 1440 minutes; shifts start at day*1440, length scenario.shift_minutes. Operations pause/resume across shifts with no unattended machining; no partial finished parts counted. Quality only observed after inspection. Costs of incomplete operations included, unused loaded stock charged; zero-good cost null.

UI saves complete session JSON locally and to downloadable file, supports restore via file validation and API reproduction; baseline plus multiple runs, prediction/reflection, trial/week, charts, conceptual animated SVG with playback speed that never enters API Settings. True quality behind explicit teaching disclosure, observed quality default.
